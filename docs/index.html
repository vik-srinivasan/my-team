Viktown

A multi-agent orchestrator that turns Claude Code into a coordinated team of specialists. Plan, implement, test, review, and ship — all from a single command.

Local-first Claude Max powered Zero API keys

What is Viktown?

An autonomous coding team that runs on your machine.

You describe what you want built. A captain agent plans the work, scouts the codebase, dispatches specialists, and orchestrates the entire development lifecycle. Engineers write code. Testers verify it. Reviewers catch bugs. A git agent opens the PR.

Everything runs locally through the claude CLI, covered by your Claude Max subscription. No API keys, no cloud services, no token billing surprises.

Each session gets its own git worktree — an isolated copy of your repo on a dedicated branch. Your main branch is never touched. When the team finishes, you get a clean pull request.

How It Works

From idea to pull request, fully automated.

  1. Create a Session

    Run team new "Add user authentication" from any git repo. Viktown creates an isolated worktree and spawns a captain agent.

  2. Scout & Plan

    The captain dispatches a scout to explore the codebase, then drafts a detailed plan with tasks, approach, and acceptance criteria. You chat to refine it.

  3. Approve

    Review the plan and say "approved." The captain locks the plan and begins execution.

  4. Execute

    Engineers implement features and write unit tests. Testers add integration tests. The reviewer checks code quality. If there are blockers, the captain loops until everything passes.

  5. Ship

    When all tasks are done, tests pass, and the review is clean — the git agent pushes the branch and opens a PR. The worktree is archived and cleaned up.

The team command — your interface to the orchestrator.

team attach <id>Re-attach to a session's chat via WebSocket

Session Data Model

Each session is fully self-contained in a git worktree.

~/team/sessions/quiet-river-42/ ... ← full copy of source repo .team/ meta.json ← session ID, title, repo, branches state.json ← phase, active specialist, blockers plan.md ← goals, approach, acceptance criteria context.md ← scout's codebase findings tasks.md ← checkboxed task lists by specialist journal.md ← append-only activity log review.md ← reviewer findings (Blocking / Suggestion / Approved) decisions.md ← ambiguity resolution log .claude/agents/ scout.md, engineer.md, ... ← specialist definitions

Agents communicate exclusively through .team/ files. No direct inter-agent messaging. The wrapper watches these files via chokidar and streams changes to the UI over WebSocket.

HTTP & WebSocket API

The wrapper daemon at 127.0.0.1:3001 exposes a full REST API.

Sessions

POST/api/sessions
Create a new session. Body: { source_repo, title }
GET/api/sessions
List all sessions with phase and metadata
GET/api/sessions/:id
Full session detail including .team/ file contents
POST/api/sessions/:id/input
Send text input to the captain. Body: { text }
POST/api/sessions/:id/approve
Approve the plan (sends "approved" to captain)
POST/api/sessions/:id/kill
Terminate a session
DELETE/api/sessions/:id
Clean up: archive .team/ and remove worktree
GET/api/sessions/:id/diff
Git diff between session branch and base branch
GET/api/sessions/:id/team/:file
Read a specific .team/ file

Notifications

GET/api/notifications
List pending notifications for blocked sessions
DELETE/api/notifications/:id
Dismiss a notification

WebSocket

WSws://127.0.0.1:3001/ws/sessions/:id
Bidirectional stream. Server sends: output, state, team_file, diff, specialist events. Client sends: input.

Quick Start

Clone to running in under 5 minutes.

Prerequisites

Node.js 22+, pnpm 11+, claude CLI authenticated, gh CLI authenticated.

Install (one time)

# Clone once to a permanent location, then never touch it again
git clone https://github.com/vik-srinivasan/viktown.git ~/.viktown
cd ~/.viktown
./setup.sh

Run

# Terminal 1 — start the daemon
team start

# Terminal 2 — create a session from any git repo
cd /path/to/your/project
team new "Add user authentication"

# Open the web UI
# http://localhost:3001

What happens next

The captain scouts your codebase, drafts a plan, and asks for approval. Once you approve, specialists implement, test, and review the code. When everything passes, a PR is opened automatically.
